P / 01

Several calendars become one dependable operational view.

The server retrieves events from multiple Microsoft 365 resource mailboxes, normalizes the information, applies mailbox and date filters, and returns a single event collection to the browser. Staff can switch between company-specific views without opening each room or vehicle calendar separately.

E / 01

The redesign extended the system without erasing what employees recognized.

The company’s existing branding, color language, and familiar calendar behavior stayed intact. The work added clearer navigation, separate visual treatments for operational areas, a dedicated holiday view, day-level detail, vehicle filters, booking links, availability states, and a structure that could support additional resources.

KeptBrand identity · familiar calendar flow · existing data sourceAddedNew views · filters · resource pages · responsive layouts · stronger status cues
A / 01

The interface is the final stop in a longer chain.

Exchange resource mailboxes supply the booking data. A Node service handles mailbox selection, deduplication, cache keys, time-zone rules, requester logic, and disabled-resource configuration before the browser renders the correct view.

CASE 03Flight tracker and route simulator
C++ graph algorithms

The project

Turn large airport and flight datasets into routes a person can actually search.

The application parses one dataset describing airports and another describing connections between them. It builds an in-memory graph capable of finding reachable routes, exploring connections, calculating trip cost, and selecting an optimal path.

DATA INGESTION

Airport records are indexed so a city, state, airport code, or name can be resolved without scanning the entire dataset each time.

GRAPH MODEL

Flights become directed connections between airport nodes, carrying details such as distance, cost, and flight number.

SEARCH STRATEGY

BFS and DFS explore the network differently; Dijkstra weighs the connections to determine the cheapest available path.

IMPLEMENTATION

Structs and classes group airport and flight information, three-dimensional vectors store flight relationships, and unordered maps provide fast airport index lookup.

03 / WORKING METHOD

I like the point where technical correctness and human experience meet.

That is why the portfolio includes infrastructure, algorithms, full-stack systems, and visual design rather than forcing every project into one category.

  1. 01
    Understand the real need

    Start with the person, task, or operational failure—not the technology I hope to use.

  2. 02
    Model the system clearly

    Identify data, states, dependencies, boundaries, and the places where assumptions can break.

  3. 03
    Make the interface explain itself

    Use hierarchy, feedback, and interaction so people do not need a separate manual for ordinary actions.

  4. 04
    Leave room for the next version

    Configuration, components, data models, and documentation should make future changes less expensive.
