A reliable process is a product too. It has users, failure states, dependencies, documentation, and maintenance.

03 / WORKING METHOD

I follow failures until they become understandable.

The technologies change. The method stays surprisingly consistent.

  1. 01
    Observe the actual behavior

    Start with what the user or system is truly doing—not what it was expected to do.

  2. 02
    Trace every boundary

    Follow identity, data, mail, API, network, and process transitions until the behavior changes.

  3. 03
    Separate symptom from cause

    Two failures can look identical at the interface while originating in completely different layers.

  4. 04
    Make the correction maintainable

    The fix should leave behind clearer configuration, logging, ownership, or documentation.
